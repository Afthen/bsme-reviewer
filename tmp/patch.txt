## Parallel tests

`node --test` already runs separate files in parallel, one process per file. Tests inside a file run one after another. So the wall time is probably set by two big files:
- `derivation_matrix_test.js` (about 67k cases, a single `test()` with Layer 1 and Layer 2 in sequence).
- `run_test.js` (1,329 lines).

I think the matrix is the real bottleneck, but I haven't measured it. Two options, both needing your go:
1. **Split the matrix by layer.** Layer 1 and Layer 2 become two files that share helpers. That's easy and roughly halves it, but only if the two layers take similar time.
2. **Shard Layer 1 by topic** across worker threads. That gives more speedup but is more machinery. The seeded `Math.random` patching in `withSeededRandom` is process-global, so workers need their own processes, not shared state.

Splitting is not narrowing under R23, but the glob in section 10 and `package.json` must list every new file. First, time each file (`node --test` with the default reporter prints durations) to confirm where the time goes.
