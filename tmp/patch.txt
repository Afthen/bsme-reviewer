You spotted the exact architectural root cause: **lifecycle event binding was coupled to menu re-rendering.**

1. `toggleBtn` and `document` click listeners lived inside `setupTopicSelector()`.
2. When the app booted in `mcq` mode (or switched modes), `setupTopicSelector()` either never ran (leaving the dropdown toggle dead—so it could open via `Choose quiz sets` but never close!) or re-ran on mode switches (stacking duplicate `toggle()` listeners so a single click fired twice).

### Root-Cause Fix
- Extract a single **`initDropdownShell()`** called **once** on `DOMContentLoaded` (just like `initSidebarView()` and `setupHeaderActions()`).
- Let `initDropdownShell()` own the toggle button, `Escape` key, and outside-click closing (ignoring triggers marked with `data-opens-dropdown`, so no `stopPropagation()` patches are needed).
- `setupTopicSelector()` and `setupMcqSelector()` become pure menu-content renderers with zero global listeners.

function closeDropdown() {

function initDropdownShell() {
  const container = document.getElementById("topic-dropdown-container");
  const toggleBtn = document.getElementById("topic-dropdown-toggle");
  const menu = document.getElementById("topic-dropdown-menu");
  if (!container || !toggleBtn || !menu) return;

  toggleBtn.addEventListener("click", () => {
    const isOpen = menu.classList.toggle("active");
    toggleBtn.classList.toggle("active", isOpen);
  });

  document.addEventListener("click", (e) => {
    if (e.target.closest("[data-opens-dropdown]")) return;
    if (!container.contains(e.target)) {
      closeDropdown();
    }
  });

  document.addEventListener("keydown", (e) => {
    if (e.key === "Escape") closeDropdown();
  });
}
