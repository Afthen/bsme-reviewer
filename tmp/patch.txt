This is a known GitHub Actions "glitch" that occurs when a workflow run is re-triggered or when a single job is re-run multiple times. Each time the `upload-pages-artifact` step runs, it adds a new artifact to the current workflow run ID rather than overwriting the previous one. When `deploy-pages` starts, it sees multiple versions of `github-pages` and crashes.

### The Diagnosis: Artifact Accumulation
In your current YAML, the **Build** (npm test) and **Deploy** steps are in the same job. If the deployment fails and you click "Re-run failed jobs," GitHub re-runs the upload step, creating a second (and eventually third) artifact for that same run.

### The Fix: Job Decoupling
The industry-standard solution for GitHub Pages is to decouple the **Build** and **Deploy** phases into two separate jobs.

1.  **The `build` job:** Handles checkout, testing, registry generation, and uploads the artifact **once**.
2.  **The `deploy` job:** Only starts if the `build` job succeeds. It consumes the artifact and pushes it to the server.

By splitting them, the `deploy` job becomes an atomic operation that doesn't re-upload the artifact if it needs to be re-tried, thus preventing artifact collision.

FILE: .github/workflows/deploy.yml
````diff
<<<<
jobs:
  deploy:
    environment:
      name: github-pages
      url: ${{ steps.deployment.outputs.page_url }}
    runs-on: ubuntu-latest
    steps:
      - uses: actions/checkout@v4
      - uses: actions/setup-node@v4
        with:
          node-version: "22"
      - run: npm test
      - uses: actions/configure-pages@v5
      - uses: actions/upload-pages-artifact@v3
        with:
          path: "."
      - id: deployment
        uses: actions/deploy-pages@v4
====
jobs:
  build:
    runs-on: ubuntu-latest
    steps:
      - uses: actions/checkout@v4
      - uses: actions/setup-node@v4
        with:
          node-version: "22"
      - run: npm test
      - uses: actions/upload-pages-artifact@v3
        with:
          path: "."

  deploy:
    needs: build
    environment:
      name: github-pages
      url: ${{ steps.deployment.outputs.page_url }}
    runs-on: ubuntu-latest
    steps:
      - id: deployment
        uses: actions/deploy-pages@v4
>>>>
````

### Why this solves the problem:
- **Isolation:** The `build` job is the only place where the artifact is created.
- **Atomicity:** If the `deploy` job fails (e.g., due to a GitHub API timeout), you can re-run just the `deploy` job. It will simply pull the existing artifact from the `build` job without creating a duplicate.
- **Efficiency:** The deployment phase no longer needs to checkout the code or setup Node.js, making the final push faster.

**Suggested Commit:** `ci: decouple build and deploy jobs to prevent github-pages artifact collision`
